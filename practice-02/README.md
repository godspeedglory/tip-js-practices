## 4. Модель данных и функции

### Модель данных

Каждая задача представлена объектом с четырьмя полями.

| Поле | Тип данных | Правила валидации |
|---|---|---|
| id | number | Положительное безопасное целое число. Идентификаторы в списке уникальны. |
| title | string | От 1 до 100 символов после удаления краевых пробелов. Внутренние пробелы сохраняются. |
| completed | boolean | При создании задачи устанавливается false. При изменении допускаются только логические значения. |
| priority | string | Допустимые значения: low, medium, high. По умолчанию medium. |

### Описание функций

**createTask(id, title, priority)** – проверяет входные
данные, нормализует название и создаёт новый объект задачи.

При успехе возвращает объект `{ ok: true, task }`.
При ошибке возвращает объект `{ ok: false, error }`.

Уникальность идентификатора проверяется при добавлении
задачи в список, поскольку createTask не получает массив задач.

**findTaskById(tasks, id)** – выполняет поиск задачи
по идентификатору с помощью метода find и строгого сравнения.
Возвращает найденный объект или undefined, если задача отсутствует.

**getPendingTasks(tasks)** – с помощью метода filter
формирует новый массив невыполненных задач.
При отсутствии подходящих задач возвращает пустой массив.

**getTaskTitles(tasks)** – с помощью метода map
формирует новый массив названий всех задач.
Порядок элементов сохраняется.
Для пустого списка возвращает пустой массив.

**getTaskStats(tasks)** – рассчитывает общее количество задач,
количество выполненных и невыполненных задач, а также процент
выполнения.

Возвращает объект `{ total, completed, pending, progress }`.
Все четыре поля имеют числовой тип.
Для пустого массива все показатели равны нулю.

Функции чтения работают с корректным массивом задач
и не изменяют исходные данные.

**addTask(tasks, id, title, priority)** – добавляет новую
задачу в конец списка. Использует createTask для проверки
данных и findTaskById для проверки уникальности идентификатора.
Новый массив создаётся с помощью spread-оператора.

**setTaskCompleted(tasks, id, completed)** – изменяет статус
выполнения задачи. Проверяет корректность идентификатора,
тип статуса и наличие задачи. Использует map и spread
для создания нового массива и нового объекта задачи.

**renameTask(tasks, id, title)** – изменяет название задачи.
Использует createTask для проверки идентификатора и названия.
Удаляет краевые пробелы и проверяет наличие задачи.
Остальные свойства задачи сохраняются.

**removeTask(tasks, id)** – удаляет задачу по идентификатору.
Проверяет корректность идентификатора и наличие задачи.
Использует filter для создания нового массива.

При успешном выполнении каждая из четырёх функций
изменения списка возвращает объект `{ ok: true, tasks }`.
При ошибке возвращается объект `{ ok: false, error }`.

Исходные массивы и объекты не изменяются ни при успешном
выполнении операций, ни при возникновении ошибок.

### Ответы на вопросы

**Почему id не равен индексу:**

Идентификатор является уникальным постоянным значением
задачи, а индекс определяет текущую позицию элемента
в массиве. При удалении элементов индексы могут изменяться,
а идентификаторы сохраняются.

**Почему getTaskStats возвращает число, а не строку с процентом:**

Числовое значение позволяет выполнять дальнейшие вычисления
без преобразования типов. Форматирование с помощью toFixed(1)
выполняется только при отображении результата в main.js.

**Какие объекты копируются при изменении задачи:**

При изменении статуса или названия создаётся новый массив
и новый объект изменяемой задачи с помощью spread-оператора.
Остальные объекты используются повторно.

Даже при повторной установке текущего значения создаются
новый массив и новый объект выбранной задачи.

При добавлении создаются новый массив и объект новой задачи.
При удалении создаётся новый массив, содержащий оставшиеся
объекты. Исходные данные сохраняются.
